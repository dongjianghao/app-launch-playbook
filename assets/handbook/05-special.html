首页 / 05 卡片与提醒

Stage 05 · Platform Features

平台特色能力，先理解规范再做

桌面万能卡片是APP_NAME最大的差异化；提醒最终走系统日历；实况窗做完后因平台限制被砍掉。 这一页重点不是“代码怎么堆”，而是“能力选择与平台规范”。

一、桌面万能卡片

2×4 横版

今天班次 + 未来七天排班。适合信息完整时使用。

2×2 竖版

只留今天，更清爽。实际宽度只有 130~160vp，布局必须单独设计。

卡片显示绝对时间，而不是倒计时

系统对卡片的定时刷新有 30 分钟下限，倒计时数字会长期不准。展示“上班时段 + 状态 + 进度 + 下一次上班时间”。

卡片深浅色跟随系统，不跟随应用内开关

中性色用 resources/base 和 resources/dark 两套资源引用，只有用户自定义班次颜色走数据。

二、班次提醒：走系统日历

把排班写进系统日历里独立的「APP_NAME排班」本地账户（CalendarType.LOCAL，不云同步），由系统日历到点提醒。

只需 READ_CALENDAR / WRITE_CALENDAR 两个普通权限，不需要申请开放能力，开发期就能验证。

规则：提醒时刻已经过去就不补提醒，只写日程。因为日历同步是“先删后建”，补提醒会重复弹窗。

已知软肋

通知由日历应用发出；如果用户关掉日历的通知权限，提醒会静默失效，而应用查不到别的应用的通知开关。UI 上要给一句排查提示。

三、实况窗：做完后砍掉

结论：v1 移除实况窗，只保留桌面卡片。

原因：平台规范限定单个实况窗最长 8 小时，超过 2 小时不更新就隐藏胶囊；而白班/夜班本身 8–12 小时，APP_NAME又刻意不做后台常驻。胶囊只能在“班次末段 2 小时且用户刚好打开过应用”时出现，价值被常驻的桌面卡片覆盖，还要额外申请开放能力。

五、Vibe Coding 提示词

1. 桌面万能卡片
请为 HarmonyOS NEXT App【APP_NAME】实现桌面万能卡片。
要求：
1. 支持 2×4 横版和 2×2 竖版两套布局
2. 2×2 实际宽度约 130-160vp，小卡片必须单独设计字号、间距、行数
3. 卡片显示绝对时间，不显示秒级倒计时：班次时段、状态、进度百分比、下一次上班时间
4. 卡片跟随系统深浅色，中性色用 resources/base 和 resources/dark 两套资源
5. 数据从 ConfigStore 读，EntryFormAbility.onUpdateForm 生成快照
6. 所有超长文本加 maxLines(1) + 省略
7. 应用内“我的”页提供添加卡片入口
2. 系统日历提醒
请把APP_NAME的班次提醒改成写入系统日历。
要求：
1. 创建本地账户“APP_NAME排班”，CalendarType.LOCAL，不云同步
2. 只申请 READ_CALENDAR / WRITE_CALENDAR
3. 把未来约 4 周排班写成日程，提醒时刻 = 班次开始时间 - 提前量
4. 提醒时刻已过去则不补提醒，只写日程
5. 同步过程串行化，避免启动时并发写重复日程
6. 清除数据时删除日程和日历账户；关闭提醒开关时只清空已排提醒
7. 导入备份后按导入的排班强制同步一次
3. 评估某个平台能力是否值得做
我在做一个 8-12 小时轮班的排班 App，考虑接入鸿蒙实况窗。
请帮我做决策，不要直接写代码。先查/解释平台规范，再回答：
1. 实况窗对单条事件的生命周期限制
2. 我的“整班倒计时”是否合规
3. 如果不做后台常驻，倒计时是否能可靠更新
4. 与桌面万能卡片相比，实况窗的增量价值是什么
5. 要不要申请这项开放能力，给出明确建议
