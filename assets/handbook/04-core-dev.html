把核心逻辑做成可单测的“纯内核”

APP_NAME的架构只有一句话：pages 负责渲染，widget 负责卡片 UI，core 负责与 UI 无关的计算和存储。 核心排班逻辑被日历、统计、卡片、提醒四条链路复用，所以必须能单测。

二、排班内核

一条规则 = 起始日期 + 循环序列 + 范围（循环 N 次 / 共 N 天 / 一直循环）。

解析优先级：手动覆盖最高；命中某条规则时，用“起始日期不晚于它的最后一条规则”，再套该规则自己的范围；起点之前、范围之外留白。

取值只有一条路径：segIndexAt() 找规则 → segKindAt() 套范围 → resolvedKind() 让手动修改盖过它。

改内核前先跑测试

正确顺序是：先 run-tests.ps1 → 再改内核 → 再跑测试 → 最后上模拟器截图。别跳步。

三、持久化的关键认知

preferences 是真相

真正落盘的是 ArkData preferences。所有“要记住”的东西，preferences 必须有副本。

AppStorage 只是镜像

AppStorage / PersistentStorage 是给 UI 用的镜像，进程被杀可能丢，不能当唯一存储。

先注册再读写

PersistentStorage 的键必须先 persistProp 注册，否则冷启动读到空值，可能把真实数据覆盖。

启动时补水，不写盘

镜像为空但磁盘有数据时，用磁盘补镜像，绝不反向覆盖。

1. 生成排班内核模型
我要在 HarmonyOS NEXT 的 ArkTS 工程里实现排班内核，代码放在 entry/src/main/ets/core/shift/ShiftModel.ets。
数据模型：
- ShiftType：name, short, color, style(实心/描边), start, end, rest, remind, countsAsWork
- CycleSeg：id, startDay(起始日), sequence(number[]), spanMode(循环N次/共N天/一直循环), spanCount
- Override：day -> typeIndex 或空
规则：
1. 规则按起始日期升序，同一天起始只保留后写的一条
2. 某天归属“起始日期不晚于它的最后一条规则”，再套该规则自己的范围
3. 规则起点之前、范围之外留白
4. 手动覆盖永远优先
要求：
1. 提供 segIndexAt / segKindAt / resolvedKind / spanDaysOf 四个核心函数
2. 所有逻辑放在 core，不依赖 UI
3. 同时写 Hypium 单元测试，覆盖边界：起始日当天、最后一天、第二天、跨天班次、老数据迁移
2. 生成持久化 ConfigStore
请为APP_NAME实现 ConfigStore.ets，负责本地持久化和 UI 镜像同步。
要求：
1. 数据存 ArkData preferences，键用 shift_store
2. 只写 AppStorage 不算落盘，所有“要记住”的值都要 load/save 成对
3. PersistentStorage 的键读写前先 persistProp 注册
4. 启动时 hydrateMirrorFromDisk：镜像为空但磁盘有数据时，用磁盘补镜像，绝不反向写盘
5. 保存时刷新桌面卡片 formProvider.updateForm
请同时处理：班次类型 types、规则 segments、手动覆盖 overrides、手动节假日标记 holidayMarks、深色 dark、提醒开关 reminderOn。
