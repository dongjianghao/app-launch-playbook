测试命令
pwsh -File YOUR_PROJECT_DIR\run-tests.ps1
pwsh -File YOUR_PROJECT_DIR\run-tests.ps1 -Device YOUR_DEVICE_ADDRESS
pwsh -File YOUR_PROJECT_DIR\run-tests.ps1 -Class '分段规则 segIndexAt / segKindAt'
注意

aa test 自己的退出码不能当依据，要看输出里的 OHOS_REPORT_RESULT: ... Failure: 0。

三、调试方法论

每个 bug 先在真机复现

复现拿不到就不改代码。很多“看起来是 bug”的其实是预期行为。

分层排除，而不是猜

先确认存储写入正确，再加日志确认模型值正确，最后收窄到渲染层。

用数据说话

调整图表刻度、柱子对齐时，写脚本读截图像素，算中心偏差，改完再测。

模拟器跑日常，真机跑验收

日常迭代在 127.0.0.1:5555；安全区、震动、卡片、通知只回真机判断。

五、Vibe Coding 提示词

1. 为核心内核补测试
请为 YOUR_PROJECT_DIR\PROJECT_NAME\entry\src\ohosTest\ets\test\ShiftModel.test.ets 补 Hypium 用例。
覆盖：
1. 范围换算与边界：起始日当天、最后一天、第二天
2. 分段规则的接管关系
3. 后一条范围结束后留白，不回退前一条
4. 同一天起始的两条只留后写的
5. 手动改班优先级
6. 老数据迁移等价性
7. 解析容错与往返
8. 跨天班次的状态与进度
9. 提醒的下一次触发时间
10. 班次类型新旧格式兼容
请保证测试只依赖 core，不依赖 UI。
2. 分层定位刷新 bug
ArkUI 里出现“数据是对的、日志是对的，但界面不刷新”的问题。
请按分层排除法给我一个排查步骤：
1. 先确认存储层写入正确
2. 再确认模型层返回值正确
3. 再确认渲染层读取的是什么状态
4. 最后给出可能的修复方案
背景：手动标记存在模块级普通 Map 里，UI 直接读这个 Map。
3. 用像素验证视觉偏差
我有一张鸿蒙模拟器截图，想验证统计图柱状图的刻度中心与柱子中心是否对齐。
请写一个 Python/Pillow 脚本：
1. 读入截图
2. 找到刻度线或柱子边缘的像素
3. 计算刻度中心与柱子中心的横向偏差
4. 输出每个柱子的偏差像素
要求：不靠肉眼，输出可量化结果。
