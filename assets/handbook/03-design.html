Stage 03 · Design System

审美替代不是玄学，而是 token 和纪律

APP_NAME的视觉经验可以总结成一句话：先锁色板、字阶、圆角、间距和动效 token，再动手做页面。 否则 AI 每次生成都会“重新发明”一套风格，最后看起来廉价。

一、设计原则

审美替代是铁律

UI/交互必须明显优于竞品，不能“能用就行”。

留白和大圆角

米白画布 + 纯白卡片 + 纯黑焦点卡，圆角 20–28px。

四个功能色

翠绿 / 琥珀 / 靛蓝 / 石板，只做语义色，不滥用彩色。

三、动效 token

动效是解释，不是装饰。

时长

交互反馈 140ms · 状态切换 220ms · 入场 360ms · 错峰间隔 40ms。

曲线

跟手用 Friction，入场用 EaseOut，出场用 EaseIn。弹簧只允许拖拽落位。

场景时长 / 曲线说明
按下反馈140ms + Friction底色变化，松手立刻恢复
展开 / 收起220ms + Frictionopacity + translate
卡片 / 列表入场360ms + EaseOut + 错峰最多 8 项，每项 40ms 间隔
页面转场进 360ms / 出 220ms二级页统一右侧滑入
拖拽落位springMotion全项目唯一允许弹的地方
进度条 / 图表400–500ms + EaseOut数据长出来，柱子错峰 10–30ms

四、图标体系

分层图标要两处一起换

AppScope/resources/base/media/ 和 entry/src/main/resources/base/media/ 都要替换；商店图标另外准备方形满幅多尺寸。

App 内图标

背景 background.png + 前景 foreground.png，合成分层图标。

商店图标

1024 / 512 / 216 / 144 / 72 五档，方形满幅不带圆角。

交互图标

装饰性图标统一加 enableAnalyzer(false).draggable(false)。

六、Vibe Coding 提示词

1. 生成设计系统
请为【APP_NAME】生成一份设计系统说明，HarmonyOS NEXT ArkUI 用。
要求：
1. 浅色 / 深色两套颜色 token
2. 圆角、间距、字号、字重 token
3. 组件规范：卡片、chip、列表行、底部 tab、空态、弹层
4. 功能色只使用：绿 #10B981、琥珀 #F59E0B、靛蓝 #6366F1、石板 #94A3B8
5. 设计原则：米白画布 + 纯白卡片 + 纯黑焦点卡，大圆角，大留白，审美替代
输出成 Markdown，字段可直接映射到 resources/base/element/color.json 和 resources/dark/element/color.json。
2. 生成动效规范
请为我的 App 写一份《动效与交互规范》，要求可执行、可验收。
核心原则：
1. 空间连续：动效从手指位置或元素来向开始
2. 克制：一屏同时动画不超过 2 处
3. 反馈优先：任何可点元素按下后 ≤150ms 必须有反应
请给出：
1. 时长 token：交互 / 状态 / 入场 / 错峰
2. 曲线 token：跟手 / 入场 / 出场
3. 按元素类型的用法表
4. 明确禁止事项
5. 验收方式
6. 项目当前落地进度记录位
3. 生成图标规范与制作脚本
我要为 HarmonyOS App【APP_NAME】准备图标。
请输出：
1. 分层图标（foreground/background）的尺寸和圆角要求
2. 商店图标需要的尺寸清单
3. 一个 Python/Pillow 脚本：读取 background.png 和 foreground.png，合成为方形满幅的多尺寸图标
4. 一个 PowerShell 方案：把生成的多尺寸图标复制到 AppScope 和 entry 两处资源目录
图标主题：日历 + 三色班次条，风格简洁，不要拟物。
